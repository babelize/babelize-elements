ثبّت مكوّنات Babelize Elements الفردية مباشرةً في مشروعك باستخدام CLI الخاص بـ shadcn.

## سجل `@babelize`

Babelize Elements مدرجة في [دليل سجلات shadcn](https://ui.shadcn.com/docs/directory) باسم `@babelize`، لذا يجدها CLI الخاص بـ shadcn دون أي إعداد.

على CLI أقدم، أو لتثبيت السجل صراحةً، أضفه إلى حقل `registries` في `components.json` لديك:

```json
{
  "registries": {
    "@babelize": "https://elements.babelize.co/r/{name}.json"
  }
}
```

## تثبيت مكوّن

ثبّت أي مكوّن:

```bash
npx shadcn@latest add @babelize/language-switcher
npx shadcn@latest add @babelize/language-switcher-pill
npx shadcn@latest add @babelize/phone-input
npx shadcn@latest add @babelize/navbar
```

يحل CLI تبعيات كل مكوّن (بما في ذلك أداة `cn`) ويكتب كل ملف إلى الاسم المستعار الذي يحدده نوعه، فالمكوّنات تذهب إلى الاسم المستعار `ui` الخاص بك، والخطافات المشتركة مثل `useControllableState` و`useListboxNavigation` تذهب إلى `lib`. إذا نقلت `ui` في `components.json`، تتبعه المكوّنات.

<Callout title="ملف `cn` لا يُمسّ">
  تستورد المكوّنات `cn` عبر الاسم المستعار `utils` الخاص بك، وتفترض أنه موجود مسبقًا، وهو الافتراض نفسه الذي تفترضه مكوّنات shadcn، إذ إن `shadcn init` يُنشئه. لا يُكتب فوق نسختك أبدًا، مهما خصّصتها.

يكتب CLI `@babelize/elements` المرفق أيضًا `cn` لك إذا كان الملف مفقودًا فعلًا، لذا يعمل في المشاريع التي لم تشغّل فيها `shadcn init` قط.

</Callout>

يمكنك أيضًا التثبيت عبر عنوان URL مباشر:

```bash
npx shadcn@latest add https://elements.babelize.co/r/language-switcher.json
```

## استيراد

```tsx
import { LanguageSwitcher } from "@/components/ui/language-switcher";
```

## استخدام CLI الخاص بـ Babelize Elements

تفضّل CLI مخصصًا؟ تأتي حزمة `@babelize/elements` مع واحد:

```bash
npx @babelize/elements add language-switcher
npx @babelize/elements list
```

يؤدي المهمة نفسها: يحل عنصر السجل، ويكتب المكوّن إلى `components/ui/`، ويثبّت تبعيات npm الخاصة به.
