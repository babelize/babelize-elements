تعمل Babelize Elements في أي مشروع React + Tailwind CSS، مثل Next.js أو Vite أو Remix، أو أي أداة تجميع أخرى لـ React. تأتي الحزمة مع أنواع TypeScript، وبإصداري ESM وCJS. وتبعيات التشغيل قليلة وقياسية في منظومة shadcn: `motion` للحركة و`lucide-react` للأيقونات.

## مدير الحزم [#package-manager]

ثبّت المكتبة كاملةً بمدير الحزم المفضل لديك:

## أخبر Tailwind بالحزمة [#tell-tailwind-about-the-package]

لا يولّد Tailwind إلا الأصناف الموجودة في ملفات مصدرك، ولا يفحص `node_modules`. من دون هذه الخطوة ستُعرض المكوّنات **بدون تنسيق**.

وجّه Tailwind إلى الحزمة المثبتة مرة واحدة:

<Tabs items={["Tailwind v4", "Tailwind v3"]}>
  <Tab value="Tailwind v4">

أضف سطر `@source` إلى ملف CSS الذي يستورد Tailwind، مع المسار النسبي إلى ذلك الملف:

```css title="app/globals.css"
@import "tailwindcss";
@source "../node_modules/@babelize/elements/dist";
```

  </Tab>
  <Tab value="Tailwind v3">

أضف الحزمة إلى `content` في إعدادات Tailwind:

```js title="tailwind.config.js"
module.exports = {
  content: ["./src/**/*.{ts,tsx}", "./node_modules/@babelize/elements/dist/**/*.js"],
};
```

  </Tab>
</Tabs>

هذه الخطوة خاصة بحزمة npm فقط. أما المكوّنات المثبتة عبر [CLI الخاص بـ shadcn](/docs/getting-started/shadcn-cli) فتعيش في شجرة مصدرك الخاصة، وTailwind يفحصها أصلًا.

## رموز السمات [#theme-tokens]

تُنسَّق المكوّنات برموز [shadcn/ui](https://ui.shadcn.com/docs/theming) الدلالية، مثل `bg-popover` و`text-muted-foreground` و`ring-ring` وغيرها، فتتبع سمة تطبيقك ونصف قطر الزوايا والوضع الداكن تلقائيًا.

**تستخدم shadcn/ui بالفعل؟** لا شيء تفعله، فـ `shadcn init` عرّف الرموز.

**لا تستخدم shadcn/ui؟** أضف الرموز مرة واحدة إلى ملف CSS الذي يستورد Tailwind. هذه سمة shadcn المحايدة، فغيّر أي قيمة لتناسب علامتك التجارية.

في Tailwind v3، اربط المتغيرات نفسها ضمن `theme.extend.colors` في `tailwind.config.js`، كما في [دليل shadcn v3](https://v3.shadcn.com/docs/theming). صُممت المكوّنات لـ Tailwind v4، وتعمل على v3 لكن بعض الأدوات الخاصة بـ v4 (مثل `shadow-xs`) لا تُحدث أثرًا.

كل مكوّن يقبل أيضًا خاصية `classNames` لتجاوزات كل جزء، فيمكنك إعادة تنسيق أي فتحة دون نسخ المصدر.

## تثبيت المكوّنات فرديًا [#install-individual-components]

تفضّل تثبيت المكوّنات واحدًا تلو الآخر مباشرةً في قاعدة كودك؟ استخدم [CLI الخاص بـ shadcn](/docs/getting-started/shadcn-cli):

```bash
npx shadcn@latest add @babelize/language-switcher
```

أو استخدم CLI المرفق داخل الحزمة:

```bash
npx @babelize/elements add language-switcher
```

في الحالتين، يُكتب المكوّن (مع أداة `cn` وتبعياته) داخل مجلد `components/ui/` لديك، وتملك الكود منذ ذلك الحين.

## تحقّق من التثبيت [#verify-installation]

استورد مكوّنًا للتأكد من أن كل شيء مُهيّأ بشكل صحيح:

```tsx
import { LanguageSwitcher } from "@babelize/elements";

export function App() {
  return (
    <LanguageSwitcher
      locales={[{ code: "en" }, { code: "fr" }, { code: "es" }]}
      defaultValue="en"
      onValueChange={(code) => console.log("changed to", code)}
    />
  );
}
```

كل مكوّن مكتوب بـ TypeScript أولًا، ويُصدّر واجهة خصائصه الخاصة، ويعمل مع `next-intl` أو `react-i18next` أو إعداد i18n المخصص لديك.
